- [ ] **CR-ITEM-SEC-5** — `ALLOWED_HOSTS = []`
  - **Severity**: Critical
  - **Location**: [backend/recruitment_platform/settings.py:30](backend/recruitment_platform/settings.py#L30)
  - **Description**: Empty list — with `DEBUG=False`, Django rejects *all* traffic. Paired with DEBUG=True, it silently accepts anything.
  - **Recommendation**: `ALLOWED_HOSTS = os.environ["DJANGO_ALLOWED_HOSTS"].split(",")`.

- [ ] **CR-ITEM-SEC-6** — Client-side-only RBAC via `localStorage.role`
  - **Severity**: Critical
  - **Location**: [frontend/recrutai/src/routes/AppRoutes.jsx:26-31](frontend/recrutai/src/routes/AppRoutes.jsx#L26-L31)
  - **Description**: `getUserRole()` reads `localStorage.user.role` and gates routes. An attacker with DevTools can set `localStorage.setItem('user', JSON.stringify({role:'RECRUITER'}))` to reveal recruiter-only UI. The backend still enforces, but UI reveals app structure, API paths, and leaks protected-view code.
  - **Recommendation**:
    1. Create `/api/users/me` returning `{role}` from the JWT-authenticated user on the server.
    2. Introduce a `<ProtectedRoute requiredRole="RECRUITER">` wrapper that verifies token presence then calls `/me` before rendering children.
    3. Never trust `localStorage.role` as a security boundary — only for UI hints.

- [ ] **CR-ITEM-SEC-7** — Unencrypted HTTP + hardcoded API URL
  - **Severity**: Critical
  - **Location**: [frontend/recrutai/src/services/api.js:4](frontend/recrutai/src/services/api.js#L4)
  - **Description**: `const API_BASE_URL = "http://127.0.0.1:8000/api"`. Ignores the already-configured `REACT_APP_BACKEND_URL` in `.env`. In production, this ships HTTP with a hostname that doesn't exist on users' machines.
  - **Recommendation**:
    ```js

    ```
    Enforce HTTPS in production (`.env.production`). Add HSTS headers at the edge.

### High

- [ ] **CR-ITEM-SEC-8** — FFmpeg subprocess with user-derived path
  - **Severity**: High
  - **Location**: [backend/interviews/views.py:85-112](backend/interviews/views.py#L85-L112)
  - **Description**: `extract_audio_ffmpeg` feeds `answer.candidate_video.path` into `subprocess.run(command, check=True)`. Argument-list form avoids shell metacharacter injection, but unusual filenames (e.g. leading `-`) can still be interpreted as flags. No media-type probe before invocation; no timeout.
  - **Recommendation**: Validate video filename matches a whitelist regex before storing. Use `command = ["ffmpeg", "-nostdin", "-i", "--", video_path, ...]` and set `timeout=60`. Constrain output path to a known media directory with `os.path.commonpath`.

- [ ] **CR-ITEM-SEC-9** — File-extension check bypassable
  - **Severity**: High
  - **Location**: [backend/users/serializers.py:108-120](backend/users/serializers.py#L108-L120)
  - **Description**: `validate_resume` checks `value.name.endswith(...)`. Attacker uploads `evil.pdf` containing arbitrary bytes; filename check passes, PyPDF2 downstream may crash or parse junk.
  - **Recommendation**: Validate MIME via `python-magic` on the first 4KB; verify file opens as a real PDF (`PyPDF2.PdfReader(...).is_encrypted` sanity-check path); reject on any parse exception.

- [ ] **CR-ITEM-SEC-10** — JWT stored in `localStorage` (XSS-exfiltratable)
  - **Severity**: High
  - **Location**: [frontend/recrutai/src/pages/login.jsx:44-46](frontend/recrutai/src/pages/login.jsx#L44-L46) and every `localStorage.getItem("accessToken")` in [api.js](frontend/recrutai/src/services/api.js).
  - **Description**: Any XSS in the app (a single dependency with `dangerouslySetInnerHTML`, a reflected input, etc.) reads the access token. Refresh tokens also live in `localStorage`.
  - **Recommendation**: Move refresh token to an `HttpOnly; Secure; SameSite=Strict` cookie issued by the backend. Keep access token in memory only; re-hydrate on reload by calling refresh endpoint. Add CSP `default-src 'self'` and disable inline scripts.

- [ ] **CR-ITEM-SEC-11** — No Axios interceptor / no refresh flow
  - **Severity**: High
  - **Location**: [frontend/recrutai/src/services/api.js](frontend/recrutai/src/services/api.js) (entire file)
  - **Description**: Every call inlines `Authorization: Bearer ${localStorage.getItem("accessToken")}`. No 401 handler, no retry-with-refresh. Expired token → confusing failures throughout the app.
  - **Recommendation**:
    ```js
    const api = axios.create({ baseURL: API_BASE_URL });
    api.interceptors.request.use(cfg => { /* attach token */ });
    api.interceptors.response.use(r => r, async err => {
      if (err.response?.status === 401) { /* refresh + retry once */ }
      throw err;
    });
    ```
    Remove per-call header wiring.

- [ ] **CR-ITEM-SEC-12** — `useAuth` context defined but never wired in
  - **Severity**: High
  - **Location**: [frontend/recrutai/src/hooks/useAuth.jsx](frontend/recrutai/src/hooks/useAuth.jsx) + [AppRoutes.jsx](frontend/recrutai/src/routes/AppRoutes.jsx)
  - **Description**: `AuthProvider` exists but never wraps the app; no component consumes it. Routing and components read `localStorage` directly. Token/role state desyncs on refresh.
  - **Recommendation**: Wrap the root in `<AuthProvider>` (in `index.js`), hydrate from backend `/me` on mount, and replace direct `localStorage` reads with `useAuth()` in components and route guards.

- [ ] **CR-ITEM-SEC-13** — No rate limiting on login or LLM endpoints
  - **Severity**: High
  - **Location**: [backend/users/views.py:40-57](backend/users/views.py#L40-L57), [backend/interviews/views.py](backend/interviews/views.py) (LLM-backed views)
  - **Description**: Credential stuffing and bill-inflation attacks are unrestricted. A single script can drain the DeepSeek budget.
  - **Recommendation**: Add `django-ratelimit` (e.g. `5/m` on login by IP, stricter by username), and a hard per-user/day cap on LLM calls in the interview flow.

- [ ] **CR-ITEM-BUG-1** — Incorrect permission-class invocation
  - **Severity**: High
  - **Location**: [backend/applications/views.py:60](backend/applications/views.py#L60)
  - **Description**: `if not IsJobSeeker():` — instantiates the permission class with no args and evaluates truthiness of the instance (always truthy), so the negation is always `False`. The guard is dead code; permission depends entirely on the `permission_classes` attribute.
  - **Recommendation**: Delete the line. Rely on the `permission_classes = [IsAuthenticated, IsJobSeeker]` on the view. If finer scoping is needed, use `self.check_permissions(request)` or `IsJobSeeker().has_permission(request, self)`.

- [ ] **CR-ITEM-PERF-1** — Whisper model loaded globally at import
  - **Severity**: High
  - **Location**: [backend/interviews/views.py:36](backend/interviews/views.py#L36)
  - **Description**: `model = whisper.load_model("small")` runs on first import. This blocks Django startup, duplicates memory per worker process, and pins ~500MB of RAM even on requests that never transcribe.
  - **Recommendation**: Lazy-load inside the Celery task (`get_model()` memoized per worker). Consider moving transcription to a dedicated worker queue so web workers stay lean.

- [ ] **CR-ITEM-BUG-2** — `setTimeout` without cleanup (memory leak + late fires)
  - **Severity**: High
  - **Location**: [frontend/recrutai/src/components/jobseeker/JobSeekerInterviewProcess.jsx:184-202, 222-237](frontend/recrutai/src/components/jobseeker/JobSeekerInterviewProcess.jsx#L184-L202)
  - **Description**: Timers started but never `clearTimeout`ed. If the user closes the interview modal mid-recording, the timeout fires on an unmounted component, may `setState` on it, and may upload a video the user abandoned.
  - **Recommendation**: Track timer IDs in a `useRef`; return a cleanup function from the owning `useEffect` that calls `clearTimeout`. Also guard state updates with an `isMounted` ref (see the pattern in `recruiter_candidate.jsx`).
